# Stable release-tag checks

The regression is shared section visibility: after a release tag appears,
`resolveReleaseTagWindowResolution` adds an `Unreleased` window. The old
`includeEmpty` branch retained it, including when empty. It can affect releases
with items too. pm-ops already strips that section in its repository wrapper.
Calendar version matching already recognized `2026.11.7` and `v2026.11.07`.

The fix keeps empty versioned releases and omits empty Unreleased sections before
limits, using the same dependency-aware section construction and candidate filter for
rendering and item diagnostics.
Default discovery also accepts unprefixed version tags and coalesces calendar
padding aliases. Explicit tag globs remain supported. New distinct historical
versions or different release boundaries remain meaningful input changes;
immutable tracker milestones provide independence from Git history.

## Review round: alias ordering, portable fixtures and flag documentation

The equal-time comparator previously chose numeric counters for some pairs and
raw spelling for others. A base release, numeric successor and `rc.1` prerelease
could form a cycle. Every pair now compares one independently derived tuple:
normalized group, suffix class, descending counter, normalized identity, then
raw spelling. The same rule handles invalid timestamps. Aliases stay contiguous
before deduplication and cannot reorder other releases.

The fixture helper refuses case-only duplicate loose refs on every filesystem,
while preserving distinct prefix/padding aliases. Uppercase-only refs still run.
The usage options row now states the versioned-release policy and the empty
Unreleased exception; every shipped options table is checked.
