# Stable release-tag checks

The regression is shared section visibility: after a release tag appears,
`resolveReleaseTagWindowResolution` adds an `Unreleased` window. The old
`includeEmpty` branch retained it, including when empty. It can affect releases
with items too. pm-ops already strips that section in its repository wrapper.
Calendar version matching already recognized `2026.11.7` and `v2026.11.07`.

The fix keeps empty versioned releases and omits empty Unreleased sections before
limits, using the same candidate filter for rendering and item diagnostics.
Default discovery also accepts unprefixed version tags and coalesces calendar
padding aliases. Explicit tag globs remain supported. New distinct historical
versions or different release boundaries remain meaningful input changes;
immutable tracker milestones provide independence from Git history.

Reproduce with `node scripts/verify-stable-check-fleet.ts <public-jira-clone>
<public-ops-clone> <public-ado-clone>`. It retains original-file results alongside
the separately generated baseline and reports tag diffs, rather than treating
regeneration as an original-file pass.

pm-jira's remaining differences are historical dependency notes and older item
ordering relative to its pinned 2026.10.31 generator. pm-ops additionally applies
its own `No tracked changes.` wording. Those consumer migration gaps are tracked
in `pmc-consumer-projection-migration`. At later pm-ops main, deleting the tag also
widens the pending Git range to include post-release PR #254; this is a changed
release boundary, not an empty-section effect. pm-ado main already contains an
empty Unreleased section, which the new policy intentionally removes; its
prepared release file passes unchanged.

Dependency-only notes currently depend on Git subjects. `GenerateChangelogOptions`
has no merged-change receipt input; tracker snapshots/milestones capture items,
not merged non-item changes. `pmc-portable-change-receipts` designs an immutable,
git-optional receipt source rather than adding another Git-only inference path.
CI's npm and Bun release gates provide the full-suite evidence at the PR head.
